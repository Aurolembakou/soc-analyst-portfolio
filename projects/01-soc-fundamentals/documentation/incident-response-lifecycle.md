# Incident Response Lifecycle

## Overview

Incident Response is the structured process used by cybersecurity teams to detect, contain, eradicate and recover from security incidents.

A SOC follows an incident response lifecycle to reduce the impact of cyber threats and restore normal operations.

---

# Incident Response Phases

## 1. Preparation

The organization prepares its security capabilities before an incident occurs.

Activities:

- Define incident response procedures
- Configure security monitoring tools
- Train security teams
- Establish communication channels
- Maintain security documentation

---

## 2. Identification

The SOC detects and analyzes suspicious activity.

Activities:

- Review security alerts
- Analyze logs
- Validate indicators of compromise (IOC)
- Determine incident severity

Questions:

- What happened?
- Which systems are affected?
- Is this a real threat?

---

## 3. Containment

The goal is to limit the impact of the incident.

Examples:

- Isolate compromised endpoints
- Block malicious IP addresses
- Disable compromised accounts
- Stop malicious processes

---

## 4. Eradication

The security team removes the root cause.

Activities:

- Remove malware
- Patch vulnerabilities
- Delete malicious accounts
- Improve security controls

---

## 5. Recovery

Systems are restored to normal operations.

Activities:

- Restore services
- Monitor affected systems
- Validate system integrity
- Confirm threat removal

---

## 6. Lessons Learned

After the incident, the team performs a review.

Activities:

- Document the incident
- Identify weaknesses
- Improve detection rules
- Update security procedures

---

# SOC Analyst Role During Incident Response

SOC analysts contribute by:

- Detecting threats
- Investigating alerts
- Collecting evidence
- Documenting findings
- Escalating incidents
- Supporting response teams
